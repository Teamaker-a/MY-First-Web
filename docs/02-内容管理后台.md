# 02 · Git 内容管理后台

> 纯静态网站 + GitHub Contents API。没有服务器、没有数据库；后台提交一次，托管平台自动构建发布。

## 入口与结构

- 后台地址：`/admin.html`（本地：http://127.0.0.1:8780/admin.html）
- 首页页脚有一个很低调的「管理」入口；没有放进主导航，也不在旅行页出现。
- 后台页面 `noindex, nofollow`，但静态站点无法隐藏 URL，真正的保护来自 GitHub Token。

新增文件：

```
site/
├─ admin.html                     # 后台页面
├─ css/
│  └─ admin.css                   # 后台样式（不影响展示页）
├─ content/
│  └─ site.json                   # 后台写入的内容：profile + articles + travel + works
└─ js/
   ├─ admin.js                    # 后台交互：登录、CRUD、上传、保存
   ├─ github-client.js            # GitHub Contents API 封装
   ├─ content-store.js            # 展示页读取 content/site.json 的入口
   └─ profile.js                  # 首页姓名 / 标语 / 短句
```

展示页只改了数据来源，没有改视觉与布局：

- 写作页：`writing-room.js` → `content-store.js` → `content/site.json`
- 文章页：`pages.js` → `content-store.js` → `content/site.json`
- 作品页：`pages.js` → `content-store.js` → `content/site.json`（作品封面可选）
- 首页：`profile.js` 把内容文件里的姓名 / 标语 / 短句写入现有元素
- 旅行页：`travel.js` → `content-store.js` → `content/site.json`
- 展示页的视觉、布局和交互没有改变；后台只是数据来源

## 登录方式

后台使用 **GitHub Fine-grained Personal Access Token** 登录，不是用户名 + 密码。纯静态站点没有后端可以安全地校验密码，所以 Token 是适合这种部署方式的登录凭据。

推荐 Token 权限：

- 只授权 **一个仓库**
- `Contents: Read and write`（用于文章 JSON 和图片）
- `Metadata: Read`（GitHub 默认需要）
- 不需要 Actions、Administration、Secrets 等权限

Token 只保存在当前标签页的 `sessionStorage`，关闭标签页或退出登录即清除；**不会**写入仓库或 `localStorage`。

## 仓库路径怎么填

后台登录页的「内容路径设置」需要按仓库实际结构填写。两个常见情况：

### A. 整个项目仓库，网站发布目录是 `site/`

```
仓库             owner/personal-website
分支             main
站点根目录       site
内容文件         site/content/site.json
文章图片目录     site/assets/images/uploads
旅行图片目录     site/assets/images/travel
作品图片目录     site/assets/images/works
```

GitHub Pages 的发布目录设成 `/site`；或者 Vercel / Netlify 的 publish directory 填 `site`。

### B. 仓库根目录就是网站根目录

```
站点根目录       （留空）
内容文件         content/site.json
文章图片目录     assets/images/uploads
旅行图片目录     assets/images/travel
作品图片目录     assets/images/works
```

如果填错，后台会提示仓库 / 内容路径不存在；不会自动猜路径。

## 使用

1. 打开 `/admin.html`，填 Token、`owner/repository` 和路径，登录。
2. 首次连接时如果仓库还没有 `content/site.json`，会载入本地示例；第一次保存会创建该文件。
3. **文章**页可以新建、编辑、删除。字段包括标题、日期、Slug、标签、摘要、正文。
4. 正文按空行分段。上传图片会插入一行：

   ```markdown
   ![图片说明](assets/images/uploads/20261101-153000-photo.jpg)
   ```

   图片会立即以一次 Git commit 提交到图片目录；文章保存后再提交内容 JSON。
5. **作品**页可以新建、编辑、删除作品。字段包括标题、类型、年份、项目链接、项目说明和一张可选封面；不上传封面时保留植物图版封面。封面会上传到 `site/assets/images/works/`，保存作品后写入内容文件。
6. **个人资料**页可以改姓名、标语、短句、邮箱、所在地、GitHub、小红书。姓名 / 标语 / 短句会在下一次构建后更新首页。
7. 保存成功后右上角出现「查看提交」，托管平台会开始自动构建。

Slug 是文章 URL 的稳定标识。写作页的新链接使用 `article.html?id=<slug>`；旧的 `article.html?id=0` 仍可打开（按数组序兼容）。改 Slug 会改变文章链接，删除文章会改变数组序，但不会影响其他 Slug。

## 内容文件格式

```json
{
  "version": 1,
  "updatedAt": "2026-11-01T00:00:00.000Z",
  "profile": {
    "name": "沈旭斐",
    "tagline": "新媒体 / 排版 / 用 AI 做点好玩的",
    "intro": "一些代码、一些旅行、一些写下来的事。",
    "email": "",
    "location": "",
    "github": "",
    "xiaohongshu": ""
  },
  "articles": [
    {
      "slug": "how-i-learned-layout-with-ai",
      "title": "我是怎么用 AI 学排版的",
      "date": "2026-10",
      "tag": "AI / 学习",
      "excerpt": "……",
      "body": ["第一段", "第二段"]
    }
  ],
  "works": [
    {
      "title": "一本书的诞生 · 对页画版图",
      "type": "排版 / HTML",
      "year": "2025",
      "desc": "用网格和字体关系，把一本书的左右页做成可以在浏览器里阅读的版图。",
      "link": "works/book/index.html",
      "accent": "#566450",
      "cover": "assets/images/works/20261103-book.jpg"
    }
  ]
}
```

- 日期使用 `YYYY-MM`（后台用月份选择器）。
- `body` 是段落数组；展示页支持把独立成段的 `![alt](路径)` 渲染为带说明的图片。
- 文章页只允许相对路径或 `https://` 图片地址，避免 `javascript:` 等危险 URL。
- 作品页从 `works` 读取；文件里还没有 `works` 时会回退 `site/js/data.js` 的示例作品。`cover` 为空时保留植物图版封面，填写后会在封面上叠加图片。


## 旅行内容管理（2026-11-02）

后台新增「旅行」页：

- 从省份下拉框添加省份（使用 DataV 完整省名，例如 `内蒙古自治区`）
- 状态：去过（粉色）/ 最想去（蓝色）/ 未点亮
- 编辑旅行标题、副标题、旅行文案
- 批量上传照片，逐张填写照片说明；第一次上传真实照片时会清除该省份的示例占位照片
- 保存后写入 `content/site.json` 的 `travel` 字段，并提交到 GitHub
- 旅行照片默认上传到 `site/assets/images/travel`，可以在登录页「旅行图片目录」中修改
- 旅行页现在也会读取 `content/site.json`；如果文件里还没有 `travel` 字段，会回退到 `site/js/data.js` 的示例数据

`travel` 结构：

```json
{
  "demo": false,
  "visited": ["浙江省"],
  "wishlist": ["云南省"],
  "places": {
    "浙江省": {
      "title": "江南的雨",
      "subtitle": "杭州 · 乌镇 · 2025 春",
      "note": "那几天一直在下雨，反而觉得江南就该是湿的。",
      "wish": false,
      "photos": [
        {
          "src": "assets/images/travel/20261102-xihu.jpg",
          "caption": "西湖边，雨刚停"
        }
      ]
    }
  }
}
```

照片建议竖版 3:4、1200×1600 以上、JPG / WebP、单张小于 500KB；路径是相对 `site/` 的网站路径。

## 作品内容管理（2026-11-03）

后台新增「作品」页：

- 左侧是全部作品列表，右侧编辑标题、类型、年份、项目链接、项目说明
- 「＋ 新作品」新建一张卡片；新建后需要保存才会写入内容文件
- 可以上传一张封面图（JPG / PNG / WebP / GIF / AVIF，单张不超过 5MB），默认上传到 `site/assets/images/works`
- 封面图会以低饱和度叠在植物图版上；没有封面时保留原来的植物图版外观
- 保存后写入 `content/site.json` 的 `works` 字段并提交到 GitHub
- 作品页通过 `content-store.js` 读取 `works`；文件里没有该字段时回退 `site/js/data.js`

`works` 结构：

```json
[
  {
    "title": "一本书的诞生 · 对页画版图",
    "type": "排版 / HTML",
    "year": "2025",
    "desc": "一句话说明这个项目做了什么。",
    "link": "https://example.com",
    "accent": "#566450",
    "cover": "assets/images/works/20261103-cover.jpg"
  }
]
```

`link` 留空或填 `#` 时，卡片仍显示「链接待补充」，点击不会跳转；外链会新开标签页。

## 发布流程

1. 后台 `PUT /repos/{owner}/{repo}/contents/{path}` 写入 JSON / 图片。
2. GitHub 仓库产生 commit。
3. 托管平台监听分支并自动构建。
4. 构建完成后展示页读取新的 `content/site.json`。

GitHub Pages 的静态发布不需要构建命令；Netlify / Vercel 需要把 publish/output 目录指向 `site`（或根据你的仓库结构调整）。

> 后台提交的是 **GitHub 仓库**。本地正在运行的 `site/` 不会自动同步；保存后需要在本地 `git pull`，线上则等托管平台完成构建。后台里的「在网站查看」也只有在构建完成后才会看到新内容。

## 安全与限制

- 静态前台无法校验密码；Token 是唯一登录凭据。不要把 Token 发给别人，不要在公共电脑上使用。
- Token 在浏览器里可见；只用最小权限、可随时撤销的 Fine-grained Token。
- 后台不能防止仓库协作者直接改 Git；Git 本身是最终事实来源。
- 删除文章或作品不会自动删除已上传的图片文件，避免误删共用图片。
- 没有草稿、版本对比、定时发布、评论审核、多用户角色；这些需要后端或更多基础设施。
- 没有自动合并冲突：多人同时保存时 GitHub 返回 409，后台会提示刷新，不会强行覆盖。
- 图片最大 5MB；支持 JPG / PNG / WebP / GIF / AVIF。
- 个人资料目前只影响首页的姓名 / 标语 / 短句；其他页面的站点品牌文字仍为静态。
- 如果之后要更省心地登录，可以加 GitHub OAuth 回调服务或自建后端；纯静态方案先使用 Token。
